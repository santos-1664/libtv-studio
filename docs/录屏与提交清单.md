# LibTV Studio 录屏与提交清单

更新日期：2026-09-16

本文件是录制脚本，不代表已经录制或生成飞书妙记。交付为无凭据、无历史数据的源码包，接收人需在自己的录制环境配置服务、创建项目并准备素材。

## 录制前准备

- 按 README 启动空白工作区，默认本地地址为 `http://127.0.0.1:3100`。
- 在录制开始前填写自己的文本、图片、视频 API URL、API Key 和模型。首次启动没有预存密钥，留空不能直接使用真实生成服务。
- 模型目录读取成功后，按需要检查文本、Agent 工具和媒体能力。录制用生成会调用所配置的服务；等待或失败时展示实际状态。
- 使用自己新建的录屏项目。下文的水杯主题是通用提示词建议，不包含历史个人作品或已经生成的媒体。
- 在飞书创建并加入会议，开启录制、共享应用窗口，确认声音和画面可用。
- 录屏不要展示 `.env`、运行数据库、主密钥、API Key 或鉴权头。配置页可以展示服务类型和模型，已保存的密钥不会回填。
- 准备 README、Dockerfile、Compose、产品方案及不含凭据的检查结果。源码交付中不加入录制环境生成的数据库、配置、素材或主密钥。

## 建议操作顺序

时间以实际模型响应为准，可在等待视频时继续演示项目管理。

| 顺序 | 操作 | 展示重点 |
| --- | --- | --- |
| 1 | 展示首页、项目和 Agent 入口，新建“录屏演示”项目。 | 从空白项目开始，三模块入口清楚。 |
| 2 | 添加文本节点，输入文案需求；添加图片与视频节点并填写参数。 | 节点可创建、拖动、缩放、编辑及连接引用。 |
| 3 | 提交文本、图片和视频生成。 | 真实任务进入等待或生成状态，结果完成后写回节点。 |
| 4 | 返回项目页，搜索、切换视图、重命名并重新打开。另建一个删除示例项目，只删除该示例。 | 项目内容独立，管理与恢复操作真实可用。 |
| 5 | 在 Agent 选择分镜 Skill，创建脚本和两个分镜。 | 流式回复、工具卡片、节点与连接写入同一项目。 |
| 6 | 要求只修改第二镜头并重新生成。 | 已有第二镜头更新，第一镜头、脚本与连接保留。 |
| 7 | 打开图片预览，播放完成的视频并展示下载。 | 使用录制环境自己生成的内容；处理中就如实展示等待。 |
| 8 | 改节点名称与位置，等待保存，刷新后重新打开。 | 内容、位置、素材和会话恢复。 |
| 9 | 展示工程目录和实际执行的测试、构建或容器状态。 | 前后端、SQLite 初始化、Dockerfile、数据卷及任务持久化。 |
| 10 | 停止飞书录制并结束会议，待转码完成后检查妙记。 | 链接可访问、画面声音完整。 |

源码包不附带已生成样例。若录制环境自行提前生成了备用成果，应明确说明是录制前生成的结果，不能冒充刚刚完成的任务。不要编造任务进度或未执行的构建结果。

## 通用演示提示词

以下内容是可重新使用的文本提示，不是个人项目记录或预先生成的作品。

**文本节点**

```text
为一款透明玻璃水杯写一句适合 5 秒产品视频的中文文案，主题是清爽日常。控制在 20 个汉字以内，只输出文案。
```

**图片节点**

```text
透明玻璃水杯放在浅色桌面上，杯中清水，窗边自然光，背景干净，真实产品摄影，构图简洁，无文字、无水印。
```

**视频节点**

设置 16:9、2 秒，使用：

```text
固定镜头，透明玻璃水杯放在浅色桌面上，阳光在水面形成柔和光斑，窗边薄纱轻轻摆动，真实摄影，运动自然，画面干净，无文字、无水印。
```

**Agent 创建分镜**

```text
为“清爽日常”规划一支 4 秒水杯产品短片。在当前项目创建一个文本脚本节点和两个视频分镜草稿，镜头序号为 1 和 2，各 2 秒、16:9。镜头 1 展示桌面环境，镜头 2 展示玻璃和水面的细节。把脚本连接到两个镜头。本轮只创建草稿，不提交生成。
```

**Agent 局部修改**

```text
只把当前项目第二镜头改为展示窗边桌面的远景并重新生成，保留 2 秒和 16:9。不要新建替代节点，保持第一镜头、脚本、其他节点和连接不变。
```

## 架构与运行展示

Docker 启动：

```bash
docker compose up --build -d
```

本地 Node 启动：

```bash
npm ci
npm run build
npm start
```

首次空白启动自动建立数据库并生成新主密钥。后续数据来自录制人自己的使用，不是源码包附带的历史数据。已有数据卷不会被初始化流程覆盖，录制前注意端口冲突。

开发阶段已有 44 项自动测试、TypeScript、Vite、Docker 构建和真实生成验证记录。它们不代表脱敏后又执行了付费测试。录制时展示自己的实际运行结果，具体开发验证与源码检查边界见 [验收记录](验收记录.md)。

## 提交检查

1. 飞书会议结束后等待转码，检查画面、声音及关键操作，获取该次录制的妙记链接。
2. 让考核指定人员拥有查看权限，并验证链接可打开。
3. 提交源码 ZIP、产品方案 Markdown 和实际妙记链接。
4. 源码 ZIP 应包含前后端、初始化逻辑、Dockerfile、Compose、锁文件、无密钥模板、文档及空 `data/.gitkeep`；不混入运行数据库、个人项目、会话、素材、密钥或主密钥。
5. 不以占位链接、本地视频路径或无关历史录制替代正式妙记链接。

提交说明可使用：

```text
任务：复刻 LibTV 专业视频创作工具
1. 项目源码：<实际提交的 ZIP 文件名>
2. 产品方案：产品方案文档.md
3. 运行录屏：<本次飞书会议产生的妙记链接>
访问权限：<考核指定查看范围>
启动与配置：按 README 启动空白工作区；源码包不含凭据和历史数据，真实生成需自行填写服务 URL、API Key 与模型。
```
