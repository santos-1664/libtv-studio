# 百炼接口接入摘要

更新日期：2026-09-16

本文保留开发阶段依据官方文档整理的协议摘要，供接收人配置和维护适配器使用。源码包不含个人 API Host、业务空间标识、API Key 或调用数据。本次文档脱敏未访问外部服务，也不代表重新执行了模型或付费验证；协议和权限以供应商当前文档及接收人账户为准。

## 配置与地域

在自己的服务控制台确认 API Host、地域、业务空间和可用模型 ID。Key、Host 与模型权限应属于匹配的地域和空间，不能因为一个地址失败就把凭据转发至其他地域。

下文用 `HOST` 代表占位域名，不含协议和路径。鉴权使用 `Authorization: Bearer <API Key>`，JSON 请求使用 `Content-Type: application/json`。占位值不能直接用于调用。

参考：[地域和域名规则](https://help.aliyun.com/zh/model-studio/regions/)。

## 模型目录

百炼原生目录为 `GET https://HOST/api/v1/models`，分页字段为 `page_no`、`page_size`，模型 ID 在 `output.models[].model`，总数在 `output.total`。

`capabilities` 描述文本生成、图片生成、视频生成或视觉理解等能力，Agent 还需工具调用支持。输入允许图像或视频不等于输出能生成对应媒体。OpenAI 兼容目录与原生目录属于不同协议，不能直接套用同一响应结构。

应用按文本、图片、视频服务分别读取目录，媒体列表只展示适配器支持的模型。源码中出现模型名称只表示协议范围，不代表接收人已获授权。

参考：[模型目录协议](https://help.aliyun.com/zh/model-studio/list-models)。

## 文本与 Agent

百炼兼容聊天端点：

```text
POST https://HOST/compatible-mode/v1/chat/completions
```

主要字段为 `model`、`messages` 和 `stream`。工具调用传 `tools`，接收 `tool_calls`；工具结果使用 `role: tool` 和对应 `tool_call_id` 回传。流式文本从 `choices[].delta` 读取，工具参数按分片拼接，完整接收后才能执行。

应用文本设置填写带 `/compatible-mode/v1` 的基地址。普通 OpenAI 兼容供应商只填根地址时，应用自动补 `/v1`；显式路径则保留，不重复添加。

参考：[OpenAI 兼容 Chat 协议](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)。

## 图片：Qwen-Image 3.0

同步接口：

```text
POST https://HOST/compatible-mode/v1/images/generations
```

顶层 JSON 使用 `model`、`prompt`、`n`、`size`。参考图通过 `image` 扩展字段传入单个 URL、Data URL 或字符串数组；没有参考图时省略该字段。该模型版本使用 JSON generations 接口处理生图与编辑，不能直接按 multipart `/images/edits` 协议发送。

开发阶段协议摘要记录的参考图限制为 1–3 张、单张不超过 10 MB。尺寸使用 `1024x1024` 形式，结果 URL 从 `data[].url` 读取，应用下载至自己的媒体目录。

其他模型版本可能采用不同的同步、异步端点和输入结构，不能仅替换模型名就假定兼容。

参考：[Qwen-Image 3.0 生成与编辑协议](https://help.aliyun.com/zh/model-studio/qwen-image-generation-and-editing-api-reference)。

## 视频：Wan 2.7

视频创建使用百炼原生异步协议：

```text
POST https://HOST/api/v1/services/aigc/video-generation/video-synthesis
```

请求除鉴权和 JSON 头外需包含 `X-DashScope-Async: enable`。文生视频使用 `model`、`input.prompt`、`parameters`，参数包含 `resolution`、`ratio`、`duration`。应用适配的 Wan 2.7 视频时长为 2–15 秒整数，模型名称示例为 `wan2.7-t2v`。

首帧图生视频使用已适配的 `wan2.7-i2v-2026-04-25` 协议：首帧放在 `input.media`，类型为 `first_frame`，值为图像 URL 或 Data URL。应用当前只接受一张首帧，输出比例跟随该图片。不能把多个参考图都标记为首帧。

创建成功保存 `output.task_id`；查询使用 `GET https://HOST/api/v1/tasks/{task_id}`。状态读取 `output.task_status`，成功视频 URL 读取 `output.video_url`。应用保存外部任务 ID、轮询状态并下载结果；未知状态和下载失败不得直接重新提交生成。

参考：[Wan 文生视频](https://help.aliyun.com/zh/model-studio/text-to-video-api-reference)、[Wan 图生视频与任务查询](https://help.aliyun.com/zh/model-studio/image-to-video-general-api-reference)。

## 视频理解与功能边界

视频理解与视频生成是不同能力。支持视频输入的理解模型可以接收视频 URL 或帧图并输出分析文本，这不等于生成视频。

当前应用尚未接入视频内容拆解。上传视频只是保存本地项目素材，不能据此宣称已理解其内容。供应商无法直接访问应用的 localhost 或相对 `/media/...` 地址，未来接入时需按协议处理实际可达 URL 或受限制的 Data URL。

参考：[视觉与视频理解](https://help.aliyun.com/zh/model-studio/vision)。
